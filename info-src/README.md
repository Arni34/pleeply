# Раздел /info — как устроен

Справочный раздел pleeply в духе docs.n8n.io. Слева меню, справа «On this page». На страницах есть карточки вариантов, у каждой страницы своя Markdown-копия, а для ИИ есть `llms.txt`.

```
info-src/
  pages/*.md     — исходники страниц (правим только их)
  docs.css       — стили
  build.mjs      — сборка, без зависимостей
  queries.json   — карта запросов ИИ (для n8n)
  QUERIES.md     — та же карта и метод, для людей
info/            — результат сборки (руками не править)
llms.txt, llms-full.txt, sitemap.xml — тоже пересобираются
```

## Добавить или обновить страницу

1. Создайте `pages/<адрес>.md`. Имя файла станет адресом: `pages/foo.md` → `/info/foo/`.
2. Вверху файла нужен frontmatter:

```
---
title: Заголовок страницы
nav: Короткое имя в меню
description: Одно-два предложения: что на странице. Идёт в meta и llms.txt.
section: start | learn | build | compare | pleeply
order: 1
updated: 2026-10-24
---
```

3. Пишите Markdown. Кроме обычного, поддерживается:
   - `> [!TIP] Заголовок` — зелёная плашка, `> [!WARNING]` — жёлтая, `> [!NOTE]` — серая;
   - блок `:::cards` … `:::` с пунктами `### [Название](/info/адрес/)` — сетка карточек, как «Choose your installation method» у n8n;
   - раздел `## FAQ` с вопросами `### …?` — сам превращается в разметку FAQPage для поисковиков.
4. Соберите: `node info-src/build.mjs`.
5. Деплой — как и раньше, из папки `pleeply`: `npx vercel deploy --prod --yes`.

Правила текста:
- первый абзац сразу отвечает на вопрос из заголовка;
- у каждой цифры есть источник в `## Sources`;
- про pleeply пишем только то, что есть на лендинге, с пометкой «в разработке, цены ожидаемые».

## Сообщество (Discourse)

Адрес форума задаётся в `site.json` → `communityUrl`. Пока он пустой, сайт собирается без сообщества.

Когда адрес задан, сборка:
- берёт у форума топ тем, последние темы, категории и статистику;
- делает страницу `/community/` в духе community.n8n.io/top;
- добавляет блок «Join the community» в конец каждой статьи, ссылку Community в меню и подвале, строки в `llms.txt` и `sitemap.xml`.

Если форум не ответил, берётся кэш `community-cache.json`.

Проверить вёрстку на чужом форуме, не трогая `site.json`:

```bash
COMMUNITY_URL=https://community.n8n.io node info-src/build.mjs
```

После проверки удалите `info-src/community-cache.json` и пересоберите без переменной.

Как создать и настроить форум — в [`../COMMUNITY_SETUP.md`](../COMMUNITY_SETUP.md). План продвижения — в [`../PROMO.md`](../PROMO.md).

## Подключение n8n (следующий шаг)

Задумано два сценария. Публикация в обоих остаётся за человеком.

1. **Мониторинг видимости, раз в неделю.** n8n берёт вопросы из `queries.json` и задаёт каждый 3 раза в Perplexity API, OpenAI (с web search) и Gemini (с Google Search). Из ответов он записывает в Google Sheets дату, движок, вопрос, процитированные адреса, упомянут ли pleeply и кто из конкурентов цитируется.
2. **Черновики по пробелам.** Если по кластеру pleeply не цитируется несколько недель подряд, n8n просит модель предложить правку или новую страницу. Черновик в формате этих `.md` с источниками уходит на проверку в Telegram или почту. После одобрения файл кладём в `pages/`, собираем и деплоим.

Что решить перед подключением:
- откуда n8n будет читать `queries.json`: папка `pleeply` пока не в git, а `info-src/` не публикуется на сайте;
- ключи API Perplexity, OpenAI и Gemini;
- в какую таблицу писать результаты.
